# ProcureWise End-User Acceptance Test

## Purpose

This checklist lets an authorised **End-User** validate the first portion of the ProcureWise workflow: account creation, PPMP planning, Purchase Request preparation, and three-supplier Pre-Canvass submission. Use only real authorised procurement information, or stop before saving any form if no legitimate test transaction is available. ProcureWise intentionally does not insert sample records.

## Before You Start

An administrator must configure the reference data listed below before an End-User can create a complete procurement package.

| Required configuration | Why it is needed | Where it is configured |
|---|---|---|
| At least one office | The Purchase Request identifies the requesting office. | **System setup** |
| At least one object of expenditure | The Purchase Request must be assigned to an expenditure classification. | **System setup** |
| At least three legitimate suppliers | Three supplier records are required to complete the mandatory Pre-Canvass comparison. | **Suppliers** |
| A current fiscal-year budget allotment that covers the intended amount | The workflow validates available funds when the package is forwarded. | **Budget Control** |

> An End-User cannot configure offices, expenditure objects, suppliers, or budgets. Those functions remain restricted to authorised administrative and procurement roles.

## Test Sequence

| Step | Route / action | Expected result |
|---|---|---|
| 1 | Open `/access?mode=register` and choose **Create End-User account**. Complete the secure identity sign-in. | On first access, ProcureWise provisions a profile with the **End-User** role and opens the dashboard. No separate password is created. |
| 2 | Open **PPMP Planning**. Add a PPMP entry only if you have an authorised planning item. | The PPMP entry is saved and becomes selectable when creating a Purchase Request. |
| 3 | Open **PPMP & Purchase Requests** and select **New Purchase Request**. | The form lets you select your PPMP entry, requesting office, object of expenditure, and enter item details. |
| 4 | Save the Purchase Request as a draft. | The PR appears in your register with **DRAFT** status. It is not yet forwarded to Procurement. |
| 5 | Open **Pre-Canvass** and select **New Pre-Canvass**. Choose the draft PR, then enter the approved budget ceiling, quotation deadline, delivery period, and evaluation basis. | A linked Pre-Canvass record opens in **DRAFT** status. |
| 6 | Use **Add quote** three times to record three different supplier quotations. Enter the amount, delivery days, compliance result, and acknowledgement details as applicable. | The Pre-Canvass table increments from `0/3` to `3/3 SUPPLIERS`; the comparison view identifies the lowest compliant quotation. |
| 7 | Select **Forward package** from the draft Pre-Canvass. | The package is forwarded to the Procurement Officer. The End-User no longer sees an action to create the Abstract, approve it, issue a PO, record delivery, or log a PMR. |

## Expected Safeguards

| Situation | Correct system behaviour |
|---|---|
| A visitor opens `/plans`, `/purchase-requests`, or `/rfq` without signing in. | The application shows **Authorized access only** with a link to the access page. |
| No office or object of expenditure exists. | Purchase Request controls remain unavailable and explain that an administrator must configure the reference data. |
| No PPMP entry has been created. | The PR form prompts the End-User to create a PPMP entry before opening a Purchase Request. |
| Fewer than three quotes are recorded. | **Forward package** remains disabled. |
| No suppliers are registered. | Quote entry cannot be completed until authorised supplier records exist. |
| The user is an End-User. | The menu exposes **Overview**, **PPMP & Purchase Requests**, **Pre-Canvass**, and **PPMP Planning** only; post-review actions remain role-gated. |

## Completion Record

After testing, record the PR number and Pre-Canvass number generated by the system, the date tested, and any error text shown. Do not delete an authentic procurement record to reset the test; request the responsible procurement administrator to handle any required corrective workflow.
